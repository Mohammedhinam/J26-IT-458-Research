## Why absent chad is not identity

The ICC notes that v2 display PCS conventions were historically ambiguous and recommends D50-adapted PCS values. This extension therefore **requires the matrix to be D50 PCS**; it does not guess that a D65-native matrix should be repaired. [ICC display-gamut guidance](https://www.color.org/displaygamut/).

For supported D65 media white, infer Bradford media-white→D50 adaptation as diagnostic evidence, and verify its consistency/recovered device colourants. **Do not multiply that adaptation into an already-D50 colourant matrix again.** Relative PCS conversion is:

`RGB code → gamma linearisation → stored D50 colourant matrix → inverse canonical sRGB D50 matrix → signed extended transfer`.

The separately derived CAT is non-identity for D65; unadapted native-D65 and double-adapted matrices are rejected. D50 white legitimately yields identity from its explicit white evidence, not from absent `chad`.

LittleCMS's matrix-shaper input uses colourants directly; its v2-display CHAD-reading path can infer adaptation from media white. These are separate operations. Cross-checks use **media-relative** source→D50 Lab, no black-point compensation or absolute-appearance claim. [LittleCMS primary source, cmsio1.c](https://github.com/mm2/Little-CMS/blob/master/src/cmsio1.c).

Matrix sums/CMS agreement cannot authenticate whether a structurally coherent but wrong camera profile is truthful. No clinical colour fidelity is established.
